# 解析原理

一份简历不论原来是 PDF、Word 还是网页，都先变成同一种中间格式（`Extracted`），再走同一套版面分析和结构识别。

```
PDF ─┐ pdf.js 取字 + 页面位图分析 ┐
DOCX ┼ 转成带排版的 HTML ─────────┼─▶ Extracted ─▶ 版面分析 ─▶ 结构识别 ─▶ 样式还原 ─▶ Resume
HTML ┘ 隔离 iframe 排版后读位置 ──┘
```

## 1. 提取（`src/parser/pdf.ts`、`html.ts`、`docx.ts`）

输出 `Extracted`：页面尺寸，以及每页上“画了什么”：

| 字段 | 内容 |
|---|---|
| `runs` | 文字片段：位置、字体、字号、粗斜体、颜色、链接 |
| `fills` | 色块（侧栏底色、模块标题底色、页眉通栏） |
| `rules` / `vrules` | 横线 / 竖线（下划线、分隔线、表格边框） |
| `markers` | 列表符号（实心圆、空心圆、方块） |
| `images` | 照片、Logo、矢量图标（裁成图片） |

- **PDF**：文字和字体信息来自 pdf.js；颜色、色块、线条、符号来自把页面渲染成位图后逐格分析（pdf.js 不直接给出这些语义）。同一行、同字体、紧挨着的字形合并成一段。
- **HTML**：在不执行脚本的隔离 iframe 里排版，读每段文字的位置和计算样式、边框、背景、列表符号。
- **DOCX**：解压后把纸张、页边距、字体、缩进、段落边框底纹、编号、右对齐制表位、表格、图片转换成等效的 HTML，再交给 HTML 提取。

## 2. 版面分析（`src/parser/layout.ts`）

- **分栏**：找一条从某个高度往下一直空着的竖向缝隙，且两侧都有足够多的文字 → 侧栏 + 主栏。
- **表格**：相交的横竖边框围成格子，没有线隔开的相邻格子合并（跨行 / 跨列）。
- **行与段落**：按基线把文字片段排成行；按行距、缩进、字号变化、列表符号把行合成段落。
- **右侧部分**：一行末尾离得很远、贴着右边界的文字（通常是时间、地点）单独作为右对齐部分。
- **富文本**：段落里与主体不同的粗细、颜色、字号写成内联样式；原稿用空格对齐的大间距用全角 / 半角空格还原宽度。

## 3. 结构识别（`src/parser/structure.ts`）

- **页眉**：第一个模块标题之前的内容；挑出证件照（第一页上部、竖向比例、尺寸合理的最大位图）。
- **模块标题**：常见标题词典（教育背景、实习经历、Projects……）+ 版式特征（字号更大 / 加粗 / 主题色 / 有底色或下划线 / 独占一行）。
- **经历**：带时间的加粗行、或与模块内其他段落外观明显不同的行作为经历标题，支持多层嵌套（公司 → 项目 → 要点）。
- **要点**：有列表符号或悬挂缩进的段落；嵌套层级按缩进和符号形状判断。
- **表格式简历**：通栏格子按正文处理并给模块加外框，其余格子保留为表格。

## 4. 样式还原（`structure.ts` 中的 `detectStyle`）

从原稿统计出一组“样式参数”（`StyleConfig`）：纸张、中西文字体、正文字号、行距、模块 / 经历 / 段落间距、页边距、主题色（出现最多的非黑非白强调色）、页眉对齐、两栏宽度与侧栏底色，以及各级标题外观（`Look`：字号倍数、粗细、颜色、底色、竖条、下划线、字间距）。

和角色外观不一样的单个段落（例如某一行特别小的灰字），把差异直接写在段落上。

## 已知局限

- 扫描件 / 图片 PDF 没有文字层，需要先做 OCR。
- 极度依赖绝对定位、文字互相重叠的设计稿式简历，结构可能识别不完整。
- 只读取前 10 页。
